# 晚饭插件使用说明

本文说明当前命令，包含 2026-10-10 加入的推荐列表与投票功能。

## 启动

项目提供已经注册 dinner 插件的 kei 启动程序，默认通过 Mock 适配器进行本地联调：

```sh
CGO_ENABLED=1 go build -o /tmp/whatfordinner-bot ./cmd/bot
KEI_STORAGE_DSN=/tmp/whatfordinner.sqlite /tmp/whatfordinner-bot -config config.yaml
```

SQLite 构建需要 C 编译器。配置中的默认监听地址为 `127.0.0.1:18080`。需要连接实际聊天平台时，在自己的 kei 启动程序中注册对应适配器，将 dinner.Plugin 加入 `kei.Options.Plugins`，并配置该平台机器人。

## 命令

| 命令 | 行为 |
|---|---|
| `/dinner` | 按当前预算和忌口查看今日推荐列表，第一次调用时生成，默认预算不限 |
| `/dinner 25` | 设置每人 25 元预算，并返回符合条件的列表；也接受 `25.00` |
| `/dinner 不限` | 取消预算限制，并返回列表 |
| `/dinner 投票 1` | 投给当前列表的编号 1，返回更新后的完整列表和票数 |
| `/dinner 推荐` | 获取个人随机推荐，使用当前会话的预算和忌口 |
| `/dinner 换一个` | 更换个人推荐，排除该个人本轮已经推荐过的候选 |
| `/dinner 已吃` | 将当前个人推荐记录为实际用餐，当天重复调用只记一次 |
| `/dinner 历史` | 查看个人最近七条实际用餐记录 |
| `/dinner 候选` | 查看维护者配置的完整清单、价格、标签和启用状态 |
| `/dinner 忌口 火锅 韩国料理` | 替换当前会话的排除标签，按候选标签精确匹配 |
| `/dinner 忌口 清空` | 清除当前会话的忌口 |
| `/dinner 帮助` | 显示命令及当前预算、忌口 |

预算命令直接使用数字或“不限”，不再使用 `/dinner 预算 ...`。金额必须大于零，最多两位小数；价格未知的餐厅不参加有限预算的抽选。没有符合条件的餐厅时明确提示，不自动放宽预算或忌口。

推荐列表最多五项，不重复。当前清单共 19 家，已移除参考人均超过 150 元的候选。有价格的餐厅参考人均为 25–143 元；`/dinner 25` 可选宜宾燃面。流浪泡泡、欢乐牧场、無燎的价格待核验，只参与 `/dinner 不限` 等不限预算抽选；比格和流浪泡泡均为鼓楼吾悦广场店。清单来源与地点核验情况见 [餐厅来源说明](restaurant-sources.md)。

## 投票规则

同一群或频道共享当天一轮列表、预算和忌口；私聊按用户分开。不同平台、机器人和群的选票互不影响。

每人一票。重复投同一编号不增加票数，改投会从原选项移走一票，再给新选项加一票。回复中的编号顺序保持固定，不按票数重新排序。

无参数查询或再次设置相同预算保留列表和选票。改变预算或忌口会清空原列表和选票，开始新一轮；群中任何用户都可以设置。每天按 `Asia/Shanghai` 零点换日，预算和忌口保留，新列表在下次查询时生成。SQLite 使用相同数据库路径重启后可恢复当天列表与选票。

生成新列表时，按发起人的实际用餐历史降低最近七天吃过的餐厅的抽选概率。列表生成后不因其他人查看或投票而重新抽选。个人推荐继续使用各自的历史降权；投票不会自动记录为“已吃”，也不会自动选择票数最高项作为个人推荐。

个人推荐和用餐历史仍按平台、机器人、用户保存，同一用户在不同群共用个人记录。未吃的个人推荐在下次执行“推荐”或“换一个”时应用当前会话条件；当天已吃的记录保留原快照。

## 本地试用

启动后，在另一个终端向 Mock 注入群消息：

```sh
curl -s http://127.0.0.1:18080/inject \
  -H 'Content-Type: application/json' \
  -d '{"text":"/dinner 100","user_id":"u1","kind":"group","channel_id":"g1"}'

curl -s http://127.0.0.1:18080/inject \
  -H 'Content-Type: application/json' \
  -d '{"text":"/dinner 投票 1","user_id":"u1","kind":"group","channel_id":"g1"}'

curl -s http://127.0.0.1:18080/sent
```

`/inject` 返回接收确认，机器人回复稍后写入 `/sent`。将 `user_id` 改为 `u2` 可体验多人投票；同一用户改投 `2` 可看到原票转移。私聊使用 `"kind":"private"` 并省略 `channel_id`。

## 维护清单

直接编辑 `config.yaml` 的 `plugins.dinner.catalog.items` 并重启。独立 catalog 模块负责校验、查询清单，投票和个人推荐复用它，不加入运行时地图查询。

```yaml
- id: stable-restaurant-id
  name: 餐厅名称
  venue: 门店地址
  price_cents: 2500
  tags: [火锅]
  enabled: true
```

`id` 必须唯一且保持稳定；价格单位为分，未知时省略；`enabled: false` 停用。已生成列表中的失效餐厅保留编号并标明不可投票，避免编号指向另一餐厅。修改价格、名称后按新配置展示；历史保留实际记录时的快照。

标签用于精确排除。当前初始清单以地图菜系分类为标签，未核验具体食材，不能据此确认过敏原。
